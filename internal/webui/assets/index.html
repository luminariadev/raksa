Quick Start in 3 Simple Steps

1 Pick Your Project

Enter your project folder in the top Project box (default . checks the current folder).

2 Run Safe Read-Only Scan

Click Scan Now or choose a Quick Check card. Raksa inspects files and settings without changing anything.

3 Fix Priority Issues

Open Issues & Fixes for plain-language steps, or ask Raksa Assistant to prioritize what matters most.

Simple Mode (Default)

  • Shows a clear health score, status label, and 1-click Quick Checks.
  • Translates technical codes into plain urgency labels and clear fix steps.
  • Includes a distraction-free Ask Raksa chat without dense sidebars.

Pro Mode (Security & SecOps)

  • Select individual L1-L6 scanners, YAML Playbooks, and Attack-vs-Defense matrix rows.
  • Inspect raw Evidence JSON, SARIF 2.1.0 exports, unified .patch diffs, and time-bound waivers.
  • Access live SSE telemetry, SHA-256 audit ledger, SIEM bridge, and 61 federated MCP tools.

What the Urgency Labels Mean

Urgent Serious exposure such as leaked credentials or open admin access. Fix immediately.
Important High-risk misconfiguration that attackers actively target. Fix before deploying.
Moderate Recommended hardening (e.g. stricter browser CSP or upload checks).
Low Minor hygiene improvement or informational defense note.

What the 6 Defense Layers Check

L1 Network:Exposed listening ports, firewall rules, and traffic baselines.
L2 Host & Server:SSH, Docker/Compose, systemd, and OS hardening.
L3 Website:HTTPS security headers, strict CSP, and web server settings.
L4 Code & CI:Leaked secrets, GitHub Actions, supply-chain and pipeline hygiene.
L5 Files & Malware:Suspicious file extensions, double extensions, and malware signatures.
L6 Security Monitor:Correlates alerts across layers into a tamper-evident ledger.

Terminal Mode (TUI) & Read-Only Guarantee

Prefer working inside a terminal or SSH session? Run raksa tui to open the same Simple-first menu ([1] Scan, [2] Issues & Fixes, [3] Ask Assistant, [4] Guide, [5] Pro Mode). Raksa runs 100% locally and never modifies source files without your explicit action.
